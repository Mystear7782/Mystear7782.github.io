# 旧アプリ（素のJS版）→ React版 機能差分

フェーズ3（React移行）の機能の差分一覧。旧版 = `legacy/`（素のJS + Supabase）。
「画面の見た目と操作は変えない」を原則とし、変えた点・追加した点・やめた点をすべて記す。

## 1. 同じもの（見た目・操作とも維持）

| 領域 | 内容 |
|---|---|
| デザイン | 旧 `style.css` をそのまま流用（色・余白・ダークモード・フォント）。ID・クラス名も維持 |
| ログイン | メール+パスワード（Supabase Auth）。未ログインではログイン画面のみ |
| 画面構成 | ダッシュボード（初期画面）、メニュー、セット記録、メニューセット、分析、体重ログ、食事記録、RM換算表、CSV、設定、フッターのタブ（ホーム/記録/セット/ボディ）とサイドバー |
| メニュー | 追加（部位・種別・名前、30全角/60半角の文字数制限）、一覧（部位グループ）、編集、アーカイブ・復元・完全削除 |
| メニューの並び替え | 行左端の「つまみ」のドラッグ（旧版もつまみ方式。長押し方式はやめていた）。4pxのしきい値も同じ |
| セット記録 | 重量・回数・1RMプレビュー、セットの追加/編集/削除、日付・時刻の変更、同日の複数セッション、`record_set` RPC |
| 有酸素 | 必須4項目と任意2項目、未入力時のトースト文言（項目名入り） |
| メニュー詳細 | 最大1RM・最大ボリューム・セッション履歴・個別CSV出力、自重運動の表示 |
| 体重・食事 | 記録/編集/削除、体重の推移グラフ、食事のP/F/C・推定カロリー・日別合計 |
| 分析 | カレンダー、メニュー別グラフ（ボリューム/最大1RM）、表、カレンダー経由の戻り先 |
| RM換算表 | 推定1RMと1〜10rep換算（四捨五入の規則も同じ） |
| CSV | 出力のBOM・列、取り込み時の未登録メニューの自動登録 |
| メニューセット | 作成・一覧・詳細・編集・削除、詳細からメニュー詳細への遷移 |

## 2. 追加したもの

| 項目 | 内容 |
|---|---|
| ログアウトとアカウント表示 | 設定画面（旧版は「設定項目はまだありません」）。ユーザー切替・ログアウトで端末の閲覧キャッシュを消去 |
| 更新バナー | 新しい版を検出すると画面上部に表示。「更新」で切り替え（旧版は `skipWaiting` で即時切り替え） |
| オフライン閲覧の強化 | TanStack QueryのIndexedDB永続化。通信なしでも過去の記録を閲覧可 |
| 画面復帰時の再取得 | アプリに戻ったとき（15秒以上経過）に最新を取得。MCPで書いた記録が反映される |
| 書き込みエラー処理の統一 | すべての書き込みで「サーバー応答を待ってからキャッシュ更新」。失敗時はトースト（簡潔な日本語）とconsole（詳細）。生のエラー文はUIに出さない |
| 一意制約のエラー表示 | 同じ部位に同名の有効なメニュー: DB（部分一意インデックス）で拒否し、「同じ部位に同名のメニューがあります」と表示 |
| CSV取り込みの重複判定強化 | CSVの session_id が一致する、または同日・同時刻・同内容のセッションはスキップ。失敗時は途中までの登録を巻き戻す |
| 分析画面の状態をURLに保持 | タブ・年月・選択日が `?tab=&y=&m=&d=` に入り、戻る/再読み込みで復元 |
| メニューセットの順序保持 | `menu_set_items.position` による並び順の保持 |
| 新規セッションの作成タイミング | 「最初のセットを保存したとき」にセッションを作る（空のセッションが残らない） |
| 画面ごとのURL | HashRouter（`#/menus` など）。戻る/進む、URL直打ち |
| DB型の共有 | `npm run gen:types` でDB型を生成し、PWAとMCPサーバーで共有 |
| テスト・CI | Vitest(ユニット)、Playwright(E2E、ローカルSupabase)、pgTAP、GitHub Actions（CI・Pagesデプロイ） |

## 3. 変更したもの

| 項目 | 旧 | 新 | 理由 |
|---|---|---|---|
| 実装 | 素のJS 1ファイル（約2300行以上）+ インラインのonclick | React + TypeScript(strict)、画面ごとの部品 | 保守性・型によるDBとの整合 |
| メニューセットの保存先 | 端末のlocalStorage(`gl_menusets`) | DB（`menu_sets`/`menu_set_items`、`save_menu_set` RPC） | 端末を替えても残る。初回に旧データを自動移行 |
| 読み取り | RPC（`get_my_*`）経由 | テーブルへの直接select（`.range` でページ分割） | 下記 4. の調査結果 |
| Service Worker | `gymlog-*`キャッシュ、Supabaseの通信も対象 | ビルド生成の `sw.js`。Supabaseは触らない。画面/JS/CSSはネットワーク優先(3秒) | 古い応答が残る不具合の根絶 |
| CSP | `unsafe-inline` あり、CDNのスクリプト | `script-src 'self'`（本番ビルド） | Chart.js等をnpmでバンドル。XSS耐性の向上 |
| 画面の切替 | `.page.active` の表示/非表示 | ルーターによる画面遷移（クラス・IDは互換で維持） | |
| ログインエラー | 実際のエラー文も表示（デバッグ用に暫定） | 「メールアドレスまたはパスワードが正しくありません」等の簡潔な文言 | 指示書の方針 |
| 自重運動の一覧の行 | 記録が無いと右側に「未記録」と表示 | 右側には何も表示しない（種別バッジのみ） | 自重運動には1RMの概念がないため（筋トレは従来どおり） |

## 4. 調査結果: 「直接selectが0件になる」現象（指示書 §8.3）

- 旧版のService Workerで再現した（旧 `sw.js` が GET の応答をURL単位でキャッシュしており、書き込み後でも以前の空配列 `[]` を返し続ける）。旧SWなしの素のfetchでは最新データが返る。DB側（RLS・権限）の問題ではない。
- 方針: React版は**テーブルへの直接selectを使う**。新Service WorkerはSupabaseへの通信に一切関与しない（TC-PWA-03とユニットテストで検証）。サーバー側の集計RPC（`get_*`）は引き続きMCPが使う。

## 5. 引き継がなかったもの（指示書 §8: 旧実装の残骸）

| 項目 | 内容 |
|---|---|
| ローカルのみ保持する旧分岐（local-keep） | DBが正のため削除 |
| `gl_menus` / `gl_sessions` の localStorage キャッシュ | TanStack Queryの永続化に置換 |
| デバッグ用ボタン・暫定のエラー表示 | 削除（DB側のデバッグ関数もフェーズ1で削除済み） |

## 6. 既知の差異・注意

| 項目 | 内容 |
|---|---|
| メニューセットの移行 | 旧 `gl_menusets` のうち、DBに存在しないメニューを参照する項目は除外し、除外件数を画面に表示する。移行後は `gl_menusets_migrated` に改名 |
| オフライン中の書き込み | 不可（エラーを知らせる）。閲覧のみ |
| 旧E2E（Python）158件 | localStorage前提で現仕様に合わないため廃止。仕様はPlaywright(TS)に移植（`test-cases-e2e.md`） |
| 旧アプリのキャッシュ | 新SWの有効化時に `gymlog-*` を削除する |
