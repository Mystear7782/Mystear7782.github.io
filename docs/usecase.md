## 詳細

### UC-01 メニューを追加する

**アクター：** ユーザー
**事前条件：** なし
**基本フロー：**
1. サイドバーから「メニューの追加」を開く
2. 部位を選択する
3. 種別を選択する（有酸素運動の場合はスキップ）
4. メニュー名を入力する（全角30文字以内）
5. 「追加する」ボタンを押す
6. トーストで完了通知が表示される

**代替フロー：**
- 同一部位に同名のメニューが存在する場合 → エラートーストを表示し追加しない
- 部位・種別・名前が未入力の場合 → 「追加する」ボタンが非活性

### UC-06 筋トレのセットを記録する

**アクター：** ユーザー
**事前条件：** 筋トレメニューが1件以上登録されている
**基本フロー：**
1. メニュー一覧からメニューを選択する
2. メニュー詳細の「新規セッション」ボタンを押す
3. セット記録画面で重量（kg）と回数を入力する
4. 推定1RMがリアルタイムで表示される
5. 「セットを追加」ボタンを押す
6. セットが一覧に追加される
7. 手順3〜6を繰り返す
8. 「詳細に戻る」で保存完了

**代替フロー：**
- セッションの日付を変更したい場合 → 日付入力フィールドから変更

---

### UC-11 有酸素運動を記録する

**アクター：** ユーザー
**事前条件：** 有酸素運動のメニューが1件以上登録されている
**基本フロー：**
1. メニュー一覧から有酸素運動メニューを選択する
2. メニュー詳細の「新規セッション」ボタンを押す
3. 専用フォームで必須項目（時間・距離・消費Cal・心拍数）を入力する
4. 任意項目（最大速度・平均速度）を入力する（省略可）
5. 「記録を保存」ボタンを押す
6. メニュー詳細に戻る

**代替フロー：**
- 必須項目が未入力の場合 → 未入力フィールド名をトーストで通知し保存しない

### UC-23 CSVをインポートして記録を取り込む

**アクター：** ユーザー
**事前条件：** インポート可能なCSVファイルが存在する
**基本フロー：**
1. サイドバーから「CSV出力 / 入力」を開く
2. 「CSVファイルを選択してインポート」ボタンをタップする
3. iPhoneのFiles appからCSVファイルを選択する
4. インポート処理が実行される
5. 結果（取込件数・新規登録メニュー数・スキップ数）が表示される

**代替フロー：**
- 重複セッション → スキップ（既存データは上書きされない）
- アプリ未登録のメニュー → 自動で新規登録してから取り込む
- session_idが空欄 → 同日同メニューを同一セッションとして取り込む
- ファイル形式が不正 → エラーメッセージを表示

### UC-32 メニュー一覧のつまみをドラッグして並び替える

**アクター：** ユーザー
**事前条件：** 同一部位に2件以上のメニューが登録されている
**基本フロー：**
1. メニュー一覧の行の左端にある「つまみ」を押す
2. そのまま上下にドラッグする（4px以上動くとドラッグ開始）
3. 他の行と交差すると順序が入れ替わって見える
4. 指を離すと並び順が確定し、DBに保存される（再読み込み後も維持される）

**代替フロー：**
- つまみを押しただけ（動かさない）→ 遷移も保存もしない
- 行本体（つまみ以外）のタップ → メニュー詳細に遷移する
- 並び替えは同一部位内のみ。他部位への移動は不可
- 保存に失敗した場合 → 元の並びに戻り、エラーを知らせる

v2.0の変更: 旧版の仕様（行の2000ms長押し）から、つまみ方式に変更した。

### UC-34 ログインする / ログアウトする

**アクター：** ユーザー
**事前条件：** Supabase Authにユーザー（メール+パスワード）が登録されている
**基本フロー（ログイン）：**
1. アプリを開くとログイン画面が表示される
2. メールアドレスとパスワードを入力して「ログイン」を押す
3. ダッシュボードが表示される。以後、再読み込みしてもログイン状態は維持される

**基本フロー（ログアウト）：**
1. サイドバーから「設定」を開く（アカウントのメールアドレスが表示されている）
2. 「ログアウト」を押す
3. ログイン画面に戻り、端末に保存した閲覧データも消える

**代替フロー：**
- 未入力、またはメールアドレス/パスワードが違う → 簡潔なエラーを表示してログイン画面にとどまる（原因の詳細は画面に出さない）
- 別のユーザーでログインした → 前のユーザーのデータは表示されない

### UC-35 直近の状況を確認し、クイック記録を始める

**アクター：** ユーザー
**基本フロー：**
1. ダッシュボード（初期画面）で、直近7日のセッション数・総ボリューム・体重変化を確認する
2. 「クイック記録」から「セット記録」「体重」「食事」を選んで各画面に移動する
3. 「最近の記録」（セッションと体重が新しい順に最大5件）の行をタップして、その記録を開く（セッションの場合、戻るとダッシュボードに戻る）

**代替フロー：**
- 記録が無い → 「まだ記録がありません」と、集計は0/—を表示
- 体重が1件だけ → 変化ではなく現在値を表示

### UC-36 体重を記録・編集・削除し、推移を確認する

**アクター：** ユーザー
**基本フロー：**
1. 下部タブの「ボディ」→「体重」を開く
2. 日付（初期値は今日）と体重を入力して記録する（同じ日に複数回記録できる）
3. 一覧の行をタップして編集（ボタンが「更新する」に変わる）、または削除（確認ダイアログ）できる
4. 2件以上あると推移グラフが表示される。一覧は日付の新しい順

**代替フロー：**
- 体重が未入力・0以下 → エラートーストを表示して保存しない

---

### UC-37 食事（P/F/C）を記録・編集・削除する

**アクター：** ユーザー
**基本フロー：**
1. 「ボディ」→「食事」を開く
2. 日付・食事の区分（朝/昼/夜/間食）・たんぱく質/脂質/炭水化物（g）を入力する。入力に合わせて推定カロリー（P×4 + F×9 + C×4）がプレビューされる
3. 記録する。保存されるカロリーはDBの生成列の値
4. 日付ごとにまとまって表示され、1日の合計カロリーが出る。編集・削除ができる

**代替フロー：**
- P/F/Cがすべて0・未入力 → エラートースト
- 編集をキャンセル → フォームが初期状態に戻る

補足: Claude（MCP）の `log_meal` でも同じ `meal_logs` に記録でき、アプリを開き直す/画面に戻ると反映される。

### UC-38 旧版のメニューセットをDBへ移行する

**アクター：** システム（初回起動時に自動）
**事前条件：** 旧アプリの localStorage に `gl_menusets` が残っている、かつDBにメニューセットが無い
**基本フロー：**
1. ログイン後、メニュー一覧とメニューセットの取得が終わると自動で移行が始まる
2. 各セットを、DBに存在するメニューだけで保存する
3. 完了すると `gl_menusets` を `gl_menusets_migrated` に改名し、作成数と除外件数をトーストで知らせる

**代替フロー：**
- DBにすでにメニューセットがある → 移行しない
- 存在しないメニューを参照していた項目 → 除外して件数を報告。メニューが1つも残らないセットは作らない
- 保存に失敗したセットがある → 改名せず、次回の起動で再試行

---

### UC-39 通信できなくても過去の記録を閲覧する

**アクター：** ユーザー
**事前条件：** 一度でも通信できる状態でアプリを開いている
**基本フロー：**
1. 通信できない状態でアプリを開く（ホーム画面のアイコンから起動）
2. アプリが起動し、保存済みのメニュー・記録・体重・食事を閲覧できる

**代替フロー：**
- 通信が遅い（3秒以内に応答がない）→ キャッシュ済みの画面とファイルで起動する
- 通信できない状態で記録・編集・削除をした → 書き込みは行われず、エラーを知らせる（オフラインの書き込みキューは持たない）

## テスト観点メモ

テストの構成と結果は `docs/test-cases-e2e.md`（E2E）、`docs/test-e2e-knowledge.md`（実行の知見）を参照。

### 単体テスト観点（Vitest）

| 対象 | テスト観点 |
|---|---|
| `orm(w, r)`（`lib/one-rm`） | 正常値・境界値（r=0, w=0）・小数点精度 |
| メニュー名の入力制限（`MenuFields`） | 全角30文字ちょうど・31文字目でカット・サロゲートペア |
| `parseCsv()`（`lib/csv`） | 引用符あり・なし・空欄・改行コード差異 |
| `importCsvText()` | 重複セッション・未登録メニュー・session_id空欄・失敗時の取り消し |
| `menuStats()`（`lib/stats`） | セッションなし・筋トレ・有酸素の分岐 |
| `migrateLegacyMenuSets()` | 存在しないメニューの除外・既存DB有りで移行しない・改名 |
| `useSortable` | 4px未満ではドラッグしない・確定時のコミット |
| Service Worker（`sw/routing`） | リクエストの分類（Supabase・同意画面は対象外）・古いファイルの判定 |

### E2Eテスト観点（Playwright）

| UC-ID | E2E観点 |
|---|---|
| UC-01 | メニュー追加→一覧に表示される |
| UC-06 | セット記録→メニュー詳細の統計値が更新される |
| UC-03/04 | アーカイブ→一覧から消える→復元→再表示される |
| UC-05 | 完全削除→メニューと記録が消える |
| UC-16〜18 | カレンダーで記録日が強調→タップ→セッション遷移→戻ると同じ月・日 |
