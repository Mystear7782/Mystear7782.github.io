## 1. プロジェクト概要

### 1.1 目的

個人の筋トレトレーニングを記録・管理するためのWebアプリケーション。スマートフォン（iPhone）のホーム画面からネイティブアプリと同等の操作感で利用できることを目指す。v1.7からは体重・食事（PFC/カロリー）の記録も対象に含む。

### 1.2 開発方針

- PWA（Progressive Web App）方式で実装し、App Store申請・Macなしで開発・公開できる構成とする
- GitHub Pagesを利用して無料でホスティングする
- **データ保存先は機能ごとに段階移行中**。メニュー管理はSupabase（クラウドDB）とlocalStorageのハイブリッド、体重ログ・食事記録はSupabase専用、セッション/セット記録は引き続きlocalStorageのみ（詳細は§2.1・§5.3）
- カスタムAPIサーバーは置かず、Supabaseの自動生成REST（PostgREST）をフロントから直接呼ぶ

### 1.3 対象ユーザー

個人利用（開発者自身）。Supabase移行により**ログイン（メール＋パスワード認証）が必須**になった。

## 2. システム構成

### 2.1 技術スタック

| 項目 | 採用技術 | 理由 |
|---|---|---|
| フロントエンド | HTML / CSS / JavaScript（バニラ） | 追加ツール不要・即時デプロイ可能 |
| フォント | Noto Sans JP（Google Fonts） | 日本語表示の視認性 |
| ホスティング | GitHub Pages（無料） | Publicリポジトリで無料利用可能 |
| **バックエンド** | **Supabase（PostgreSQL + Auth + PostgREST）** | **マネージドサービスでサーバー運用不要。無料枠内で運用可能** |
| データ保存（メニュー管理） | Supabase（`exercises`テーブル）＋localStorageキャッシュ | 読み取りはRPC経由、書き込みは直接、オフライン時はローカルキャッシュにフォールバック |
| データ保存（セッション・セット・メニューセット） | localStorage（未移行） | フェーズ2として今後Supabase化予定 |
| データ保存（体重ログ・食事記録） | Supabase専用（localStorage非経由） | 新規機能のため最初からクラウド保存 |
| オフライン対応 | Service Worker | PWAとして動作させるために必要 |
| グラフ描画 | Chart.js 4.4.1（CDN遅延読み込み、SRI検証付き） | 分析詳細画面・体重推移グラフの表示 |

### 2.2 システム構成図

```
開発環境（Windows PC）
　└── VS Code でコード編集
　└── Git でバージョン管理

GitHub（Publicリポジトリ）
　└── main ブランチに push → GitHub Pages に自動反映

Supabase（プロジェクト: swncmbsamxoyjeojwbyc）
　└── Auth（メール+パスワード認証）
　└── PostgreSQL（RLSで行単位アクセス制御）

　└── セッション・セット記録: 引き続きlocalStorageのみ（端末内）
```

## 5. 非機能要件

### 5.1 動作環境

| 項目 | 要件 |
|---|---|
| 対象端末 | iPhone（Safari / PWAモード） |
| オフライン動作 | メニュー閲覧・セッション/セット記録は可能（要ログイン済みキャッシュ）。**体重ログ・食事記録はオンライン必須**（Supabase専用のため） |
| ダークモード | 端末設定に自動連動（`prefers-color-scheme`） |
| フォント | Noto Sans JP |

### 5.2 セキュリティ

| 項目 | 方針 |
|---|---|
| データ保存先 | メニュー管理: Supabase＋localStorageキャッシュ／体重・食事記録: Supabaseのみ／セッション・セット: iPhone本体のlocalStorage |
| 認証 | Supabase Auth（メール＋パスワード）。**RLS（行レベルセキュリティ）により他ユーザーのデータは参照・変更不可** |
| GitHub リポジトリ | Public（コードは公開されるがデータは非公開） |
| APIキー等の機密情報 | publishable key（`sb_publishable_...`）はクライアント埋め込み前提の公開キーのため`supabase-client.js`への直書き可。**secret key（`sb_secret_...`）は絶対にコードに含めない** |
| HTTPS | GitHub Pagesにより自動有効 |
| HTMLエスケープ | メニュー名・部位・種別・セット名等、利用者由来の全テキストを`esc()`関数で`innerHTML`挿入前にエスケープ（R-01） |
| CSP | `<meta>`タグで`default-src 'self'`を基本とし、Chart.js/Supabase JS SDK配信元（cdnjs・**cdn.jsdelivr.net**）・Google Fontsを許可。**`connect-src`にSupabaseプロジェクトURLを追加**（新規） |
| SRI | 動的読み込みするChart.js・**Supabase JS SDK**（新規）に`integrity`属性（sha384/sha512）と`crossorigin`を付与 |
| 検索エンジン対策 | robots.txtで必要に応じてクロール制限（将来対応） |

詳細な方針・実装箇所は`詳細設計書`§11・§12を参照。

### 5.3 データ保存

| 項目 | 内容 |
|---|---|
| 保存方式（メニュー管理） | Supabase `exercises`テーブル（読み取りはRPC関数経由、書き込みは直接）＋localStorage（`gl_menus`、オフライン時のフォールバック用キャッシュ） |
| 保存方式（セッション・セット・メニューセット） | localStorage（キー: `gl_sessions`, `gl_menusets`）。**未移行（フェーズ2）** |
| 保存方式（体重ログ・食事記録） | Supabase `body_weight_logs` / `meal_logs`テーブルのみ。**localStorageは経由しない** |
| 消失リスク | localStorage部分（セッション・セット）はSafariのデータ消去操作・機種変更時・PWAアイコン削除時に消失の可能性あり。Supabase保存分（メニュー・体重・食事）はクラウド側に残るため端末側の事情では消失しない |
| バックアップ手段 | CSVエクスポート機能（セッション・セットが対象。メニューセット・体重・食事記録はCSV対象外） |
| データ移行 | 旧形式（`gl_history`）から新形式（`gl_sessions`）への自動マイグレーション実装済み。2026年9月、iPhone側で`gl_sessions`が空になるデータ消失インシデントが発生し、9/12時点のCSVバックアップから338セッション・1046セットを復旧（詳細設計書§13参照） |

### 5.4 注意事項（PWAアイコン更新時）

iPhoneのホーム画面からPWAアイコンを削除するとlocalStorageも消去される。**セッション・セット記録はSupabase移行が完了するまで引き続きこのリスクの対象**なので、アイコン更新時は必ずCSVエクスポートでバックアップを取ること。安全な更新手順は以下の通り。

```
1. CSVエクスポートでデータをバックアップ
2. ホーム画面のアイコンを削除せず、SafariでURLを直接開く
3. 「ホーム画面に追加」で新しいアイコンとして再追加
4. 旧アイコンを削除（この時点では新アイコン側にデータがある）
```

体重ログ・食事記録・メニュー管理（Supabase保存分）はこの手順の影響を受けない。

## 6. デプロイ・運用

### 6.1 デプロイ手順

```
1. main ブランチに変更を push
2. GitHub Pages に自動反映（数分以内）
3. iPhoneでアプリスイッチャーから完全終了 → 再起動で反映
```

### 6.2 Service Workerのバージョン管理方針

| 状況 | 対応 |
|---|---|
| index.html・app.js・style.cssの変更 | バージョン変更不要（ネットワーク優先で自動更新） |
| sw.js自体のロジック変更 | `CACHE`定数のバージョンを上げる |
| 古いキャッシュによる不具合 | バージョンを上げてpush |

### 6.3 PWA更新が反映されない場合の対処

1. アプリスイッチャーから完全終了 → 再起動
2. それでも反映されない場合：SafariでURLを直接開き「ホーム画面に追加」で再追加（データ消失に注意。Supabase保存分は影響なし）

### 6.4 Supabaseプロジェクト運用
